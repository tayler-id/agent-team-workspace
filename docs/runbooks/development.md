# Development

Runs from TypeScript source under Node type stripping. P0b readiness requires exactly Node 24.21.0 (`.node-version`, the unchanged specification pin) and pnpm 10.34.1 (`packageManager`); the broader `engines` ranges are installation compatibility, not qualification. There is no build step yet.

Run `node scripts/ci-doctor.mjs --json` before behavioral tests, even when pnpm cannot start. `node --test scripts/test/ci-doctor.test.ts` proves positives, missing/wrong prerequisites and each omitted-probe denial in disposable copies. Exit 2 is blocked infrastructure, never behavioral red. The doctor installs nothing and does not qualify PostgreSQL, Swift, browser, mandatory CI or hosted enforcement. See [toolchain readiness](../site/ci.md).

On macOS, a signed host launcher can reject the correctly installed Rolldown addon with different Team IDs. Select an approved unwrapped Node 24.21.0 executable on PATH, then repeat the frozen install and doctor. Do not delete the lockfile, add WASM as a direct dependency, alter signatures or globally disable scripts. P0b changed no dependency or lifecycle policy; preserve optional dependencies. A fresh isolated store and the same installed tree under official Node proved this diagnosis; receipts are in `evidence/ci/P0b/`. Doctor scratch copies are removed in `finally`; evidence survives.

## Commands

| Command | What it does |
| --- | --- |
| `pnpm install --frozen-lockfile` | Installs the locked dependency set for all workspace packages |
| `pnpm typecheck` | Strict workspace compilation, then a separate ES2024-only client-core compile with no Node or DOM globals |
| `pnpm lint` | Strict typed lint plus import and transitive public-type boundaries |
| `pnpm boundaries` | Lane 8: forbidden import forms, public SDK/DOM leaks, private-path exports and no-platform compile negatives |
| `pnpm docs:check` | markdownlint over authored Markdown, then the semantic design gate |
| `pnpm contracts:generate` | Bundles the schema families with the OpenAPI operations and regenerates the TypeScript and Swift consumers |
| `pnpm contracts:check` | Regenerates into a clean directory and fails on any byte of drift or any schema keyword outside the tested subset |
| `pnpm contracts:conform` | Runs the golden vectors through the TypeScript and Swift consumers and prints the joint report |
| `pnpm client:replay -- --json --swift` | Public lane-7 fixture driver, comparing literal replay snapshots in the core and independent generated-value Swift consumer |
| `pnpm test` | Unit and PostgreSQL tests against a throwaway cluster |
| `pnpm test:unit` | Unit/contract tests; wrapper lifecycle tests also require PostgreSQL 18 binaries |
| `pnpm test:pg` | PostgreSQL tests only, throwaway cluster |
| `pnpm migrate` | Applies pending migrations as the owner in `AGORA_MIGRATION_DATABASE_URL` and prints a JSON report |
| `pnpm check` | Lint, typecheck, docs, contract drift and tests; not the doctor, standalone design negatives, public probe or foundation gate |

The documentation tool's TOML parser is pinned to `smol-toml` 1.7.1 through a narrow workspace override. Its upstream 1.7.0 pin hangs on a malformed trailing comment (CVE-2026-85730); a bounded public-CLI regression test and full dependency audit cover this repair.

## Packages

| Package | Root | Owns | Must not import |
| --- | --- | --- | --- |
| `@agora/contracts` | `contracts` | JSON Schema families, OpenAPI operations, generated consumers, canonical JSON, the pinned Ajv wire validator | Anything but schema tooling; never domain, storage, Hono, React or transport code |
| `@agora/domain` | `packages/domain` | Pure decisions, branded identifiers | Hono, Drizzle, pg, React |
| `@agora/client-core` | `packages/client-core` | Immutable normalized snapshots, synchronization, drafts and command decisions | Frameworks, transports, domain/server/storage internals |
| `@agora/storage` | `packages/storage` | Migrations, explicit SQL, the `Database` handle | Hono, React; it never exports pg types |
| `@agora/center` | `apps/center` | Hono routes and composition | Raw SQL |

Import boundaries are enforced by package export maps and the `agora/import-boundary`, `agora/public-types` and `agora/renderer-footgun` ESLint rules on guarded `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs` and `.cjs` sources under packages/contracts/apps src trees and the entire `apps/web/**` tree. The first checks value/type-only imports, dynamic imports, import types, re-exports, CommonJS import syntax, owning-package paths, ambient DOM references, `apps/web` Feature/framework/client/host owners and public entrypoints, and rejects relative imports that leave `apps/web/src`. It rejects unprovable dynamic targets and names the supported owner in diagnostics. The second follows public export types through aliases, generics, inheritance, callbacks and nested fields, so a private SDK type cannot hide behind a domain port. The third confines raw React effect imports (including string-literal import names) and default/namespace React surfaces to `apps/web/src/framework`, treats unresolved value references from TypeScript's `lib.dom.d.ts` globals as Host/framework-only (including ambient `declare` shadows), denies DOM-node mutation including computed literal keys and mutator unions such as `'remove' | 'normalize'` (not ordinary writers such as `URLSearchParams.append`), and rejects `dangerouslySetInnerHTML`, bare `@ts-ignore` and inline ESLint disables. `linterOptions.noInlineConfig` owns disable suppression for Agora rules. Contracts plain JS keeps import-boundary without a public-types type-info loader crash. `pnpm typecheck` runs `apps/web/tsconfig.json` alongside the root and client-core projects and excludes `apps/web` from the root program. The exact contract-schema wildcard is the only permitted wildcard export; private code paths remain closed. `pnpm boundaries` includes `packages/client-core/test/app-architecture.test.ts`. Architecture exceptions are only valid rows in `agora/architecture-exceptions.json` (exact path, symbol, guard, rationale, owner, independent approver, YYYY-MM-DD expiry and an existing compensating test); symbols may be bare packages, scoped packages, relative targets, ambient global names or `dynamic-import` for unprovable targets, and the file is validated when ESLint loads even with no violations. The guard list holds only rules that consult the registry: `agora/import-boundary` and `agora/renderer-footgun`.

The core imports only its own utilities and generated types through `@agora/contracts/values`. Domain canonicalization uses the narrow `@agora/contracts/canonical` export, not the validator facade. The center has an empty export map: its Hono factory is private composition, while its HTTP fixture remains public. Tests of the factory live inside that package. Generated TypeScript receives boundary checks without rewriting installer/generator bytes; its index-signature formatting is exempt only from the conflicting style rule.

## Contracts

`contracts/schemas/*.schema.json` (one JSON Schema 2020-12 file per wire family, every component a `$defs` entry) and `contracts/openapi.json` (OpenAPI 3.1.1 operations only) are the authoritative wire sources. There is no handwritten TypeScript, Zod or Swift wire type; the center takes its report types from the generated consumer. `contracts/tools/generate.mjs` rewrites the family `$ref`s into `#/components/schemas/Name`, rejects any keyword outside the subset both generators represent faithfully (closed objects, string and integer enums, anchored ASCII patterns, bounded integers, arrays with items; no `oneOf`, `null`, `number`, `const`, `$defs` inside a component or shorthand regex classes), validates every family with Ajv, then writes `contracts/generated/openapi.bundled.json`, `contracts/generated/typescript/openapi.d.ts` (openapi-typescript 7.13.0), the Swift files under `contracts/swift/Sources/AgoraContracts/Generated/` (swift-openapi-generator 1.13.1, run through SwiftPM from `contracts/swift/Package.swift`) and `contracts/generated/manifest.json` with source and output digests. Generated files are regenerated, never edited; `pnpm check` runs the drift check.

`contracts/fixtures/vectors.json` holds the golden vectors: exact wire bytes per component with the expected acceptance, canonical RFC 8785 bytes, SHA-256 digest and, where present, a detached Ed25519 signature from a fixture-only key. `contracts/src/conform-cli.ts` runs them through the TypeScript consumer (Ajv plus `canonicalJson`) and the Swift consumer (`agora-contracts-conform`: generated types, a runtime validator over the bundled document, CryptoKit) and fails on any disagreement. A missing Swift toolchain exits 3 (unavailable) and is never a pass. The first Swift build fetches the pinned packages recorded in `contracts/swift/Package.resolved` and takes a few minutes; `contracts/swift/.build/` is a cache, not evidence.

### Synchronization fixture

`sync.schema.json` supplies reusable R07 `StreamCursor` and `CommandReceipt` values. `fixture-sync.schema.json` supplies only non-production snapshot and closed message-revision, tombstone and run-card payloads. All use generated consumers and the same validation/conformance commands. No HTTP operation references these fixture types. Separate event components keep each payload closed without widening the generator subset. A later fixture adapter translates them into neutral core inputs; the core must not export fixture types or know fixture kind names.

`created_seq` identifies the first visible message position and stays fixed across edits. `last_seen_room_seq` covers the whole room stream, but unread counts only visible positions created after it. Edits, tombstones and run updates do not create unread positions; delivery never advances reading state. Cross-record consistency and replay are core transitions, not JSON Schema validation. These fixtures establish no production conversation schema or authorization.

### Local room family

`local-room.schema.json` (`agora.local-room/v1`) holds the conversation contracts of the loopback-only local-development room: `LocalRoomScope`, `RoomAuthor` (`human` or `local_agent`), `RecordCitation`, `RoomMessageBody` (1 to 4096 scalars), `SendRoomMessageCommand`, `CommandIdentity` (`command_id` plus the canonical `request_digest`), `RoomMessage`, `RoomMessageCreatedEvent`, `RoomSnapshot` and `RoomCommandReceipt`. It reuses `StreamCursor` and `CommandReceipt` from `sync.schema.json` and `ErrorReport` from `errors.schema.json`. `POST /api/v1/local-room/messages` and `GET /api/v1/local-room/snapshot` are its operations; `command_conflict` in `errors.schema.json` is the 409 of a reused command with a changed digest. The domain ports, the fixed room identity `LOCAL_ROOM` and the send decision live in `packages/domain/src/local-room/port.ts`, the event kind in `events.ts`; `node scripts/probe-center.mjs --scenarios` prints the probe inventory without starting anything. `docs/site/local-room.md` is the feature page.

### Local room persistence

Migration `0001_local_room.sql` creates the `local_room` schema (`room` counter, `message`, `event`, `command_receipt`), seeds the one fixed room, forces row-level security keyed on `agora.scope_id` = project id, grants `agora_app` select plus the `next_seq` column update on the room and select plus insert on the record tables, and refuses every update or delete through triggers. `Database.withLocalRoom(projectId, work, { readOnly })` binds one transaction to one project; `createPostgresLocalRoom(database, LOCAL_ROOM)` in `packages/storage/src/local-room.ts` composes the port, and `apps/center/src/main.ts` is the only place it is composed. The send locks the room counter row, replays or refuses by command identity, checks citations, then inserts the message, its event at the same sequence and the receipt; the caller's commit or rollback covers all four writes. Tests: `packages/storage/test/local-room.pg.test.ts` and `apps/center/test/local-room.pg.test.ts` (the latter spawns the real process and restarts it).

### Framework-independent client core

`@agora/client-core` exports `initialState` and `synchronize(state, input)`. Inputs are internal, transport-neutral projections using generated UUID, revision, digest and receipt values through the types-only `@agora/contracts/values` export. They are not a second wire schema. `scripts/client-fixture.ts` validates the fixture wire values before translating them; neither fixture names nor generated fixture types enter the core API.

A transition returns a deeply immutable state plus explicit requests and acknowledgements. Adapters execute requests; the core opens no connection and authorizes nothing. Snapshots replace the relevant stream, retain newer known record revisions, and replay strictly after the accepted cursor. Events dedupe by stream/sequence, buffer at most 1,000 out-of-order entries, and acknowledge only the applied contiguous prefix. Replay-floor loss or overflow requests a fresh snapshot. Unknown state changes retain the projection and cursor, set synchronization mode to `upgrade`, and block further events until a supported snapshot arrives. Other streams remain independent.

Reading is explicit and monotone. Drafts remain `unsent` across snapshot/route changes; `clear` for logout or revocation erases all private state. Browser session-storage integration is not implemented here. A receipt settles its known pending command but never advances a stream cursor. Retry decisions keep the original command ID and request digest, honor offline/rate waits, stop on denial, and request refreshed state after stale revisions. These are retries of idempotent Agora commands, never direct provider calls or a billable-call retry policy. No privileged offline queue is created.

`contracts/fixtures/replay.json` contains test vectors, not production API payload definitions. `pnpm client:replay -- --json --swift` drives six literal ordered/gap/duplicate/unknown/stale-revision snapshots independently through TypeScript and Swift. Remove `--swift` for the pure Node driver; absence of Swift with that flag exits 3, not pass. `--file` selects a reviewed local vector file. `packages/client-core/test/guards.test.ts` disables guards only in disposable source copies and requires their public assertions to fail. Lane 8 is `pnpm boundaries`, with native JSON at `.scratch/boundaries.json`; foundation readiness remains a separate, unqualified gate. The [client synchronization feature page](../features/client-synchronization.md) explains the behavior and includes a state visual.

## PostgreSQL test path

CI P0c A allocates, B integrates and C qualifies the unchanged socket allocator in `scripts/postgres-socket.ts` through the wrapper below. Run `pnpm exec vitest run --project unit packages/storage/test/postgres-socket.test.ts --disableConsoleIntercept` for allocation, ownership denials and source-copy mutations. `allocatePostgresSocket(artifactDir, runId?)` canonicalizes the existing artifact path, requires a UUIDv4, and exclusively creates `/tmp/agora-p0c-<runId>` (canonical `/private/tmp` on macOS), mode 0700. Keep the returned identity with the run record; call `verify()` before use and `cleanup()` only after all socket users stop. Cleanup requires matching directory inode/device, user, permissions and exact 0600 ownership bytes; foreign, symlinked or nonempty resources are refused, never recursively removed. Evidence is outside this directory and untouched. This is accidental cross-run isolation, not a sandbox against hostile code running as the same OS user. B proves deep paths and owned lifecycle cleanup. C proves that disabling any guard turns its named assertion red and records the lifecycle receipts under `evidence/ci/P0c/C/`. No schema, role or authentication policy changes here.

`scripts/with-test-postgres.mjs` runs `initdb`, directly starts an owned PostgreSQL process group on the short socket with trust authentication, creates the non-superuser schema owner `agora_owner`, the non-owner login role `agora_app`, the guard-negative role `agora_bypass` and the database `agora_test` (the bootstrap superuser `postgres` is exported as `AGORA_TEST_SUPERUSER_DATABASE_URL` and used only by the test that removes and restores the `agora_app` prerequisite; that test renames a cluster-level role, so point the exported URLs at a disposable server only), runs one command with `AGORA_TEST_DATABASE_URL` (app), `AGORA_TEST_OWNER_DATABASE_URL` (owner), `AGORA_DATABASE_URL` (app) and `AGORA_MIGRATION_DATABASE_URL` (owner) set, then stops and deletes the cluster. Trust authentication is acceptable only because no TCP port is opened, the socket directory is private to the user, and the cluster lives for one command.

Startup (initialization, readiness and role setup together) defaults to 30 seconds; `AGORA_PG_STARTUP_TIMEOUT_MS` accepts integers 1..300000. `TMPDIR` controls data/log placement, never socket length. NDJSON stderr records `allocated`, `starting`, `started` and `cleaned` identities. Wrapper SIGINT/SIGTERM exit 130/143; a signaled command retains legacy exit 1; startup/cleanup failure exits 70. A failed `initdb` or `psql` carries the last 4 KiB of the tool's own stderr in its `blocked` message. A missing or unspawnable `pg_isready` fails the startup once instead of reporting every 25 ms until the deadline. Owned groups receive termination then SIGKILL after one second, including command descendants. A group the wrapper cannot signal is reported once as `blocked` with `stop failed`, forces exit 70, and the wrapper keeps waiting for its command rather than crashing out of cleanup. Cleanup never adopts PID files; ambiguous ownership reports `cleanup-failed` and retains resources for inspection. External-server mode owns only its command group, not the server. The command itself has no wall-time deadline. SIGKILL of the wrapper or descendants that deliberately escape its process group are outside this local trusted-tool boundary. Two more limits are recorded by C. On macOS a SIGKILLed postmaster, whether by the one-second fallback or from outside, leaves its 56-byte System V shared memory interlock segment behind; `kern.sysv.shmmni` allows 32, after which every new cluster fails with `could not create shared memory segment`. The wrapper test suite and the C drivers reclaim only the segment whose creator is the run's own recorded postmaster, after proving that creator dead and the segment unattached, and every run asserts zero run-owned segments at its end. A postmaster killed from outside those runs still leaves one, and so does the bootstrap backend of an `initdb` interrupted by SIGINT, which no `starting` receipt names; list them with `ipcs -ma` and remove unattached segments whose creator pid is dead with `ipcrm -m <id>`. A same-user listener bound at the exact dead postmaster socket path, with the lock untouched, is treated as that postmaster's stale socket and unlinked; same-user hostile code is outside the boundary.

Application code connects as `agora_app`. That role owns nothing, and the fixture tables force row-level security, so the policies bind every role without `BYPASSRLS`, the owner included. Migrations run as the owner. The test cluster also creates `agora_bypass`, a `BYPASSRLS` member of `agora_app`, used only by the guard-negative test. The pg test project fails with `blocked prerequisite` when the URLs are missing; it never skips.

## Migrations

Reviewed SQL lives in `packages/storage/drizzle/NNNN_name.sql` and is listed in `packages/storage/drizzle/meta/_journal.json`. The Drizzle migrator records applied entries in `drizzle.__drizzle_migrations`, so a second run applies nothing. `pnpm migrate` prints `applied`, `total`, a catalog-based `schema_digest` covering relations, columns, constraints, indexes, row security, policies and grants, and the server version. Exit codes: 0 pass, 2 blocked prerequisite, 64 usage error, 70 infrastructure failure.

Roles are cluster-level and are an operator prerequisite, never created by a migration. Before the first `pnpm migrate`, create the non-owner service role and the schema owner, for example `CREATE ROLE agora_app LOGIN NOSUPERUSER NOBYPASSRLS` and `CREATE ROLE agora_owner LOGIN NOSUPERUSER CREATEDB`, then create the database owned by `agora_owner`. Migrations grant table access to `agora_app`; a missing role blocks the migration with exit 2 and a message naming it. Point `AGORA_DATABASE_URL` at `agora_app` (or a login member of it) and `AGORA_MIGRATION_DATABASE_URL` at the owner. Policies apply to every role; membership governs only the grants.

The foundation fixture schema `foundation_fixture` is a non-production namespace. Nothing in it can authorize a production operation.

## Center

`apps/center/src/main.ts` serves on `127.0.0.1:$PORT` and needs `AGORA_DATABASE_URL`, which must belong to the non-owner service role. Public routes:

| Route | Behavior |
| --- | --- |
| `GET /api/v1/health` | Liveness, never touches a dependency |
| `GET /api/v1/health/ready` | 200 when the database answers `select 1`, else 503 |
| `POST /api/v1/fixture/policy/decisions` | Validates `FixturePolicyCommand` through the shared wire validator (Ajv 2020-12, no coercion, defaults or removal), answers the pure scope decision |
| `POST /api/v1/local-room/messages` | Validates `SendRoomMessageCommand`, converts it to domain values with the canonical request digest and dispatches to the composed `LocalRoomPort`; `main.ts` composes the PostgreSQL adapter, so a valid command answers 201 with a `RoomCommandReceipt`, a replay the original receipt, a changed body 409 `command_conflict`, another scope 404 `scope_mismatch`, an unknown citation 404 `not_found`; a process without an adapter answers 404 `unavailable_capability` |
| `GET /api/v1/local-room/snapshot` | `RoomSnapshot` of the fixed room from one repeatable read, at most the latest 1000 messages |

Unknown routes and malformed commands answer JSON with a stable `reason_code` and a `correlation_id`.

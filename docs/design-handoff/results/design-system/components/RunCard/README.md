# RunCard

One run as a row: the delegate's tinted mark, the run and task numbers, owner and placement, the committed state as a chip, and at most one action.

The tint is the delegate's identity and stays the same across the timeline, the runs list and the phone home, so a person can follow one agent through the product by colour. The chip is the run's committed state from Control, never the delegate's last sentence.

## Variants

Every run state via the chip vocabulary. Live states get the live chip; lost, unconfirmed and unavailable get a neutral chip with the question glyph; a superseded attempt keeps its tint but takes the archive glyph and the hist chip.

## Facts, always present

Owner, delegate, placement, last progress. Reserved and used budget with the payer when the run is live. Head and trust class when it has evidence.

## Do

- Keep one action per row, phrased as what it does: Open, Answer, Recover, Review.
- Show authority and cleanup separately on a cancelled or lost run.
- Keep the historical row visible with its tint.

## Do not

- Do not take state from prose.
- Do not colour the chip with the agent's tint.
- Do not imply a reserved budget is enough to finish.

# Application architecture boundaries

## What it is

Agora's application architecture mechanical boundaries: Feature, Client, Host and framework **import ownership** and **renderer foot-guns** enforced through the existing ESLint boundary owner rather than a second lint framework. B1 extends package import rules across guarded source extensions and reserves `apps/web` owners. B2a adds a structured **architecture-exception registry**, the only way to let a named path import a named symbol past a guard. B2b adds renderer foot-gun checks on top of that registry. B3 closes five bypasses an independent re-review found in B2b's checks and one false positive.

## What it does

`agora/import-boundary` rejects renderer imports of storage, domain implementation, server packages, `pg`, Hono and Drizzle, blocks every non-Feature importer (framework/client/host and un-owned `apps/web/src` folders) from importing product Features, rejects a Feature-to-Feature import whose target is absent from the importer's `apps/web/src/features/<name>/dependencies.json` (a JSON array of Feature names, one entry per name; an absent file declares nothing, and invalid JSON, a non-array, a non-name entry, a duplicate or a self-entry is rejected as malformed), requires Feature-to-Feature and Feature-or-other-to-framework/client/host edges to use public `index.ts` entrypoints so a two-hop relay through `apps/web/src/util` cannot bypass owners, keeps portable client-core free of application code, and rejects relative imports that leave `apps/web/src` (so `apps/web/test` or `apps/web/lib` relocation cannot bypass owner rules). It also scans every comment for a JSDoc `@type {import('mod').X}` edge, so a `.js`/`.mjs`/`.cjs` file with no `TSImportType` AST node cannot smuggle a forbidden module past the guard in a type-position comment. `agora/renderer-footgun` allows raw React effect imports (including string-literal import names such as `import { 'useEffect' as ue }`) and default/namespace React surfaces only under `apps/web/src/framework`, while a default/namespace import of the compiler-emitted `react/jsx-runtime` or `react/jsx-dev-runtime` (no effect surface) is allowed everywhere. It treats unresolved browser capabilities from TypeScript's `lib.dom.d.ts` as Host/framework-only value references (ambient `declare` shadows do not hide them), denies DOM-node mutation including computed literal keys and mutator unions such as `'append' | 'prepend'` and `'remove' | 'normalize'` while allowing ordinary writers such as `URLSearchParams.append`, denies the `setAttribute`/`removeAttribute`(`NS`)/`toggleAttribute`/`insertAdjacentText` method family the same receiver-aware way, and denies `innerHTML`/`outerHTML`/`textContent`/`style` property **assignment** on a DOM host plus any property assignment on a `CSSStyleDeclaration` receiver (`el.style.color = x`). Every receiver check also re-checks the pre-cast expression through `as`/`<T>`/`!`/`satisfies`, so wrapping a real DOM element in an unrelated type cannot hide a mutation from the checker. In a `.mjs`/`.cjs` file under `tseslint.configs.disableTypeChecked` (no type checker at all), every named mutator — ambiguous or exclusive — is trusted by name, closing the gap where an ambiguous mutator previously went unchecked for lack of type information. It also forbids `dangerouslySetInnerHTML`, bare `@ts-ignore` and inline ESLint disables. Diagnostics name the supported owner or path. Guarded roots cover `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs` and `.cjs` under packages/contracts/apps src trees and the entire `apps/web/**` tree, including contracts plain JS/CJS. `linterOptions.noInlineConfig` owns disable suppression so a comment cannot silence Agora rules. `pnpm typecheck` includes `apps/web/tsconfig.json` and excludes `apps/web` from the root program so the DOM-aware lane is the only lane that compiles web sources. Exceptions live only in `agora/architecture-exceptions.json`. A row names one exact file path, one exact symbol (a package, a relative target, an ambient global name or `dynamic-import`), one guard (`agora/import-boundary` or `agora/renderer-footgun`), a rationale, an owner, a different approver, a `YYYY-MM-DD` expiry and an existing compensating test. Wildcards, directories, expired rows, unknown guards and self-approval are rejected, and ESLint refuses to load at all while the committed file is invalid. A row covers every literal import form of its symbol on its path and nothing else.

## Why it exists

Unsafe renderer and import shortcuts must fail in lint and tests, not in prose review. Reserved owners keep later Client/Host and Feature discovery slices from inventing a parallel policy. Widening the owner table is a test-visible architecture-policy change.

## How it works

```flow
Authoring | Write Feature, Client, Host or framework code under its reserved apps/web owner.
Load | eslint.config.js validates agora/architecture-exceptions.json before any rule runs and fails closed on a bad row.
Lint | ESLint runs agora/import-boundary and agora/renderer-footgun on .ts/.tsx/.mts/.cts/.js/.jsx/.mjs/.cjs under guarded roots.
Dependency | A Feature may import another Feature only if its own dependencies.json names it, and then only through that Feature's index.ts. Framework, Client and Host never import any Feature, declared or not.
Diagnostic | A rejection names the supported owner or public entrypoint, not only a rule id.
Exception | Only a reviewed agora/architecture-exceptions.json row can allow a named path and symbol.
Proof | packages/client-core/test/app-architecture.test.ts keeps positive, negative and guard-weakening fixtures.
Hardening | B3 reproduces each reported bypass through the public CLI first, then closes it: JSDoc import() comments, DOM property/setAttribute mutation, untyped .mjs/.cjs mutators and cast evasion, while allowing the react/jsx-runtime namespace.
```

These slices do not implement Client/Host runtime, product UI, Pretext or browser-shell migration. Build-time Feature discovery is a separate slice, documented in [Feature discovery](feature-discovery.md). Owner paths are reserved in policy constants; extension and adversarial fixtures are generated at test runtime. The committed exception file is empty; the live-rule fixture writes rows into it and restores it byte for byte.

## Implementation status

**Built for per-Feature `dependencies.json` enforcement (U20.B02: declared imports allowed, undeclared and malformed rejected, framework-to-Feature denied; the lint reads the file on every check and does no discovery), import-boundary ownership (B1), the exception registry (B2a), renderer foot-guns (B2b) and the B3 bypass-closing pass.** No product Feature behavior ships here; B3 also relocated two DOM writes from `apps/web/src/main.tsx` into the Host adapter (`renderMountError`) that the newly-checked property-assignment rule correctly flagged, with no change to the rendered output.

## U20 lane evidence

**What.** `pnpm -s agora project lanes --unit U20 --task agora-u20-lane-evidence --artifacts evidence/U20 --json` runs the ten live lanes of the unit plan against the lint that already exists. [One vitest driver](repo:packages/verification/test/u20-lanes.test.ts) writes `lane-N/assertions.json`, `transcript.log` and `scenario.html` for each lane. The runner passes only when all ten ran and passed with none skipped, and the driver writes `outcome.json` with `qualification: not_claimed`. `pnpm -s agora project verify --scenario perf --unit U20 --json` measures lint time separately.

**Why.** The B01 and B02 receipts prove each rule on its own task. The unit plan also asks for ten scenarios with exact messages, a trunk comparison, a guard that must turn red, and the paused renderer fixture. This driver produces those artifacts from real lint runs. It adds no rule and changes no product code, and a pass does not qualify U20 or open a foundation gate.

**How.** Lanes 2 to 7 and 9 lint accepted and rejected probe files in uniquely named Features under the real `eslint.config.js`. Lane 5 lints with a copy of that config whose extension list has no `tsx`, and the lane 2 assertion must fail there. Lane 1 lints the same `.ts` and `.tsx` fixtures through the CLI in the head checkout, in a clone of `--parent` and in a clone of `9bb7462^`, the commit before `.tsx` joined the guarded files, each with its own offline install. It requires head to keep every `agora/` rule either older tree reports for a `.ts` file, and records what each tree said about `.tsx`, including a parse error. Lane 8 reads the renderer files of commit `99aa4f7` with `git show`, places them under a throwaway Feature path with their original folder layout, and requires raw effects, direct `document` use and Client-owned state to show up as rejections. Lane 10 runs the `pnpm boundaries` test files in one vitest run and requires the `.tsx` rows among the passes. Parse errors fail a lane, so an unparsed file cannot pass as accepted.

The [diagram](repo:docs/site/u20-lane-evidence.svg) draws the same flow. The site publishes it as a source record, so open the SVG from a checkout to see the drawing. `scenario.png` comes from `chrome-devtools-axi` rendering each lane's `scenario.html`, which is a page of that lane's retained assertions and not a product screen. When the tool is missing the lane keeps its transcript and records that no image exists. The lane folders and `outcome.json` live directly under `evidence/U20/`. The red and green runs, guard negatives, perf receipt and notes live under `evidence/U20/lane-evidence/`.

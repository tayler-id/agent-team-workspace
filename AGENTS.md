# Agora contributor guide

This repository holds the design baseline, official project-local pstack skills, and the executable test-first foundation started by `agora-s1-bootstrap-repository` (U01a.B01). No product feature exists yet.

- Read `docs/technical-spec.md` for authoritative behavior and boundaries.
- Use `docs/implementation-plan.md` for delivery units and `docs/task-breakdown.md` for dependency-aware tasks. Only S1 belongs in the first-release queue.
- Read `docs/research-basis.md` for evidence and `docs/decisions.tsv` for the append-only decision trail.
- R21 owns language-neutral contracts and import boundaries. R22 owns mandatory test-first, guard-negative, feature-map and foundation gates. No product feature or write-enabled agent precedes the executable foundation; each task closes on its own proof, not its unfinished milestone.
- R25 owns the Agora application architecture: Feature, Entrypoint, Timeline Card, Client and Host, plus its mechanical contract. R26 owns conversational agent creation and the Bug Agent role, planned S2/S3 capabilities. R25's U20 boundary lint (`.ts`/`.tsx` import ownership and renderer foot-guns, see `docs/site/app-architecture.md`) is built; feature discovery, the Client/Host boundary and migration (U21-U23) and all of R26 are specified, not implemented. `docs/site/agora-application-architecture.md` explains the full R25 contract for a developer, and units U20 through U25 in `docs/implementation-plan.md` sequence the build. Use only Agora-owned terminology for this architecture; see `docs/research-basis.md#agora-application-architecture-provenance` for the naming restriction and why.
- Use the official skills under `.agents/skills/`. R22 overrides the bundled TDD skill's optional-test fallback and model-specific lane assumptions. Preserve all installer bytes and metadata; do not run setup-pstack implicitly.
- Run `node scripts/verify-design.mjs` and `node scripts/test-design-checks.mjs` for authoritative design checks; `node scripts/test-naming-guard.mjs` covers the case-insensitive, package-name-aware banned-architecture-label rule (D96/D103; see `docs/research-basis.md#agora-application-architecture-provenance` for the restriction) separately, so it never depends on repairing the unrelated `test-design-checks.mjs` baseline. Run the unchanged pstack plan checker as an informational format check. `docs/validation/design-validation.md` records commands and limits; design validation is not runtime foundation readiness.
- Wire contracts: `contracts/schemas/*.schema.json` and `contracts/openapi.json` are the only authored wire sources; `pnpm contracts:generate` regenerates the TypeScript and Swift consumers, `pnpm contracts:check` rejects drift and out-of-subset keywords, `pnpm contracts:conform` runs the golden vectors through both consumers. `docs/runbooks/development.md` has the subset and layout.
- Mandatory local checks: nothing lands on local `main` without a passing receipt for that exact commit. `node scripts/local-checks.mjs run` (needs the exact `.node-version` Node), `verify <rev>`, `install` (once per clone, and again after the tool or hook changes) and `status`; `docs/site/local-checks.md` states what git enforces and what the Firstmate landing tool must call.
- Project controls: `pnpm -s agora project` and the independent Python fixture expose owned lifecycle and retained proof, not product authority. `.agents/skills/verify-agora/SKILL.md` is the literal setup/drive/cleanup recipe; `docs/site/project-controls.md` explains Python prerequisites, namespaces and local trust limits.
- Code gates: `pnpm check` runs lint, typecheck, docs, contract drift and tests. `pnpm boundaries` exercises import/export, no-platform compile negatives and application-architecture fixtures (Feature/Client/Host owners under `apps/web`, renderer foot-guns, exact-row `agora/architecture-exceptions.json` validated when ESLint loads). `pnpm test` boots a throwaway PostgreSQL 18 cluster; the pg tests block rather than skip without one. When clusters stop starting with `could not create shared memory segment`, follow the runbook's `ipcrm` recovery for segments left by SIGKILLed postmasters. `docs/runbooks/development.md` and `docs/site/app-architecture.md` explain commands, package boundaries, the PostgreSQL test path and migrations. `packages/client-core/test/app-architecture.test.ts`'s setup/cleanup only creates and removes the `ownerStubs` paths (`apps/web/src/{framework,client,host}/index.ts`, two feature stubs) it did not find on disk; a path that already holds real product code, such as the apps/web Host barrel, is left untouched on both setup and `afterAll`.
- `docs/design-handoff/` is the designer-facing packet (entry `README.md`); `node scripts/verify-design-handoff.mjs` checks its sections, links, diagrams, stage labels, private paths and size. It proposes presentation only; product behavior stays in `docs/technical-spec.md`.
- Every behavior change lands with its test, a feature-map entry in `agora/feature-map.json`, and `red.log`/`green.log` from `node scripts/record-red-green.mjs` under `evidence/<unit>/<task>/`. The recorder only carries `.ts` test paths to the parent; a `.tsx` test such as `apps/web/test/app.test.tsx` needs a hand-applied parent-worktree red run (`evidence/local-room/usability-fixes/README.md` shows one). `.agents/skills/verify-agora/SKILL.md` holds the literal Doctor, Launch, Drive, Evidence and Cleanup commands. `node scripts/validate-evidence.mjs --dir evidence/<unit>/<task>` (U01b.B02) re-checks a recorded bundle's exact head/base/config, artifact digests, exit/outcome and owner-attested producer signature against the repository and the bundle's own `manifest.json`; see `docs/site/evidence-validator.md`.

- The local-development room lands in five gated slices (proposal at `99aa4f7:evidence/local-room/preservation/size-split-proposal.md`). Keep contracts, events, dispatch and adapters independently movable. `docs/site/local-room.md` and `node scripts/local-room.ts --help` own the L3 runtime/CLI scope; `.agents/skills/verify-agora/SKILL.md` owns launch, replay and owned cleanup proof. Receipts live under `evidence/local-room/<slice>/`; ordinary stop retains data and only explicit stopped-instance reset deletes disposable data. `@agora/domain/local-answer` is a separate deterministic read-only L5 preparation slice (context, citations, proposals) with no runtime/UI/CLI trigger and no posted response yet. L4's first vertical slice is landed: `apps/web/src/host/live.ts` wires the apps/web room shell to the live L1-L3 runtime (`scripts/local-room-service.ts` now builds `apps/web/src/main-live.tsx`, not a separate plain-DOM harness); real connection state with manual disconnect/reconnect and per-command delivery feedback (sending/retrying/waiting_connection/delivered/failed, with a Discard affordance on a permanent denial) are also landed, see `docs/site/local-room.md#per-command-delivery-feedback`; unsent drafts that survive reload (`sessionStorage`, bound to the snapshot response's `x-agora-instance` header, fail-closed) are landed, see `docs/site/local-room.md#unsent-drafts-across-reload`; remaining L4 scope (measurements, a VoiceOver pass) stays open, see `docs/site/local-room.md#live-room-ui`. `evidence/handoff/README.md` is the latest consolidation handoff: integrated branches, open approvals and remaining work.
- The `apps/web` room shell (`App.tsx`, `host/fixture.ts`) is a size-bound reviewed re-split of the original candidate branches `fm/agora-local-room-web-shell` and `fm/agora-web-framework-client-host`: their separate `Composer.tsx`/`Timeline.tsx`/`store.ts`/`projection.ts`/`transport/port.ts`/`fixture/adapter.ts`/`fixtureTransport.ts` modules were consolidated inline to meet the per-slice file/line bound, not dropped. Both branches are preserved as real merge-commit ancestors of `main` for source provenance; do not resurrect their modular files as unwired duplicates.
- Timeline virtualization (`@tanstack/react-virtual` behind `apps/web/src/framework/useTimelineVirtualizer.ts`, text sizing via `@chenglou/pretext` behind `apps/web/src/host/pretext.ts`) populates the previously-reserved `apps/web/src/framework/` owner; see `docs/site/local-room-timeline-virtualization.md` and `evidence/local-room/virtualization/salvage-inventory.md` for the per-file source mapping and its own real-merge provenance (`fm/agora-browser-pretext-virtualization`, `archive/agora-browser-pretext-virtualization-dirty-snapshot`).

- Implementation is incomplete without its documentation page and explanatory visual in the same change. Follow `docs/site/authoring.md` for both audience tracks, atlas ownership and independent committed-code/evidence review; `pnpm docs:build` enforces the site contract.

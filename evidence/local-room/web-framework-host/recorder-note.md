# Red/green recorder note

`node scripts/record-red-green.mjs --parent 9a8fe09 --head eb7e818 --out evidence/local-room/web-framework-host -- pnpm exec vitest run --project unit apps/web/test/fixture.test.ts packages/client-core/test/app-architecture.test.ts` failed reproducibly (4 attempts) with `ENOENT` reading `apps/web/src/host/index.ts` from inside its own `agora-green-*` temp worktree, even though `existsSync` on that same path returned `true` moments earlier in the same process. The identical file also disappeared from this task's own primary worktree mid-run (confirmed via `git status --short apps/web/src/host/` showing it deleted, then restored with `git checkout --`), and from a plain `/tmp` worktree not using the tool's `agora-*` naming convention once, but not on repeated manual replays outside the recorder.

The real cause, found later by an independent review, was `packages/client-core/test/app-architecture.test.ts`'s own `afterAll`: it deleted every path in a fixed `ownerStubs` list unconditionally, and `apps/web/src/host/index.ts` was on that list even after this slice landed a real barrel there. Running the suite anywhere (this recorder, `pnpm check`, a plain `vitest run`) deleted the file deterministically, with no other agent or process involved; a single-process, non-concurrent rerun reproduced it every time. This slice's `syncOwnerStubs`/`cleanupOwnerStubs` now only creates and later removes stubs that were missing on setup, so a path holding real content is never touched. The "shared multi-agent environment reaping paths" theory above was wrong; it is recorded here only so a future reader does not re-chase it.

`red.log` and `green.log` in this directory were captured by manually reproducing the recorder's own methodology instead: a real `git worktree add --detach` at the parent revision with the head's two test files copied in (`apps/web/test/fixture.test.ts`, `packages/client-core/test/app-architecture.test.ts`), `pnpm install --frozen-lockfile --prefer-offline`, then the same focused `vitest run` command (red, exit 1, both files failing for real behavioral reasons: the module doesn't exist at the parent, and the new owner assertion is false); then the same command at the head worktree as-is (green, exit 0, 21 passed). `test-patch.diff` is the literal `git diff` of those two test files between parent and head, matching what the recorder would have applied.

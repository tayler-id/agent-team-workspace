# Local room unread boundary

Task `agora-live-room-unread-boundary`. Closes the `Timeline` gap noted in [`docs/site/local-room.md`](repo:docs/site/local-room.md#live-room-ui), measured against [`docs/design-handoff/results/design-system/components/Screen-Room/`](repo:docs/design-handoff/results/design-system/components/Screen-Room/README.md) and [`TimelineMessage/README.md`](repo:docs/design-handoff/results/design-system/components/TimelineMessage/README.md): "the unread boundary is a live chip with the count and a faint live rule."

## What changed

- `apps/web/src/components/Timeline.tsx`: the first-unread marker (`row.firstUnread`) now renders a chip (`N new` with a small live dot) followed by a hairline rule that fills the rest of the row, instead of plain centered `New` text. `Timeline` computes `unreadCount` once from `rows` (`rows.filter(unread).length`, the same boolean each row already carries) and passes it to `MessageRow`. The marker's accessible name becomes `Unread messages start here, N new`, so a screen reader gets the count without waiting for the header's debounced announcement. The unread cursor, message order, virtualization, and `Mark room as read` are unchanged; only this element's markup, styling, and accessible label moved.
- `apps/web/src/fixture.css`: `.unread-boundary` is now a flex row (`chip` + `i` hairline). The dot uses a new `--signal-live: #8b6cf6` token (design handoff's `signal-live`, used only as the 8px dot's fill, never as a border, outline, or text color). The rule uses the existing neutral `--muted` for contrast against the unread row's tinted background; the design handoff's own `hairline` value is visually identical to this app's `--border` and disappears against that tint, so `--muted` is the closer neutral match once the marker sits inside a tinted row rather than on a plain white timeline. The dot's pulse inherits the page's existing global `prefers-reduced-motion: reduce` rule (`fixture.css`'s `animation-duration: .001ms !important`), so no separate reduced-motion rule was needed.
- `apps/web/test/app.test.tsx`: extended the existing live-room unread-transition test (arrivals from another tab, the same single local principal posting through a separate client, not just an empty room) with assertions that the marker's accessible name and visible chip text track the real unread count at 1 and at 2, and that it disappears after **Mark room as read**.
- `docs/site/local-room.md`: documented the marker's new presentation and accessible name under "Unread, announcements and touch targets," and closed the `Timeline` bullet in the baseline-gap list (the remaining gap there is unrelated: typed-work-object tiles, not the boundary).

Deliberately **not** touched: the unread cursor/`firstUnread` logic in `packages/web-framework/src/projection.ts`, message focus, keyboard navigation, virtualization, or the debounced `aria-live` status announcement in `App.tsx` — all out of scope for a presentation-only change. No fake members, navigation, identity, or multi-person claims were added.

## Intended shape when work resumes

- Contracts: add `command_conflict` to `errors.schema.json` (R07 409 for a duplicate command with a different digest); add `GET /api/v1/local-room/snapshot` returning `RoomSnapshot` to `openapi.json`; give the send operation a 409 response; regenerate both consumers; one accept vector for the new reason code.
- Domain (`packages/domain/src/local-room/`): `port.ts` keeps the dispatch port (`send`, `snapshot`) and adds the append/read store port (`lockRoom`, `findReceipt`, `findMessages`, `append`, `readSnapshot`) plus the pure `sendRoomMessage(store, identity, command)` decision: lock the room row first, then replay when the stored digest matches, deny `command_conflict` when it differs, deny `not_found` for a citation that names no persisted message at that sequence, otherwise append. `events.ts` owns the `local_room.message_created` event shape and its constructor. The fixed local-development identity (project, room, human principal) lives beside the port; the command's scope must equal it.
- Storage: migration `0001_local_room.sql` with schema `local_room`, tables `room` (counter, seeded with the one fixed room), `message`, `event` (foreign key on `(project_id, stream_id, seq)` to the message so event sequence equals room sequence structurally), `command_receipt` (primary key `(project_id, actor, command_id)`); forced row-level security keyed on `agora.scope_id` = project id; `agora_app` gets SELECT and column-level UPDATE(next_seq) on `room`, SELECT and INSERT only on the three record tables; BEFORE UPDATE OR DELETE triggers refuse changes to records for every role. `Database.withLocalRoom(projectId, work, { readOnly })` shares one transaction helper with `withScope`; snapshots read under repeatable read. `createPostgresLocalRoom(database, identity)` composes the port.
- Center: `CenterDependencies.localRoom` optional with the L1 unsupported adapter as the explicit default so the health, policy and readiness tests stay unchanged; a status table maps `scope_mismatch` and `not_found` to 404, `command_conflict` to 409, `unavailable_capability` to 404; `main.ts` composes the PostgreSQL adapter with the fixed identity; the request digest is `digestCanonical` over the validated wire command.
- Tests: `apps/center/test/local-room.test.ts` becomes `local-room.pg.test.ts`, spawns the real center process against the throwaway cluster and drives HTTP for send, replay, conflict, scope, citation, validation-before-storage, snapshot and restart; at the L1 parent it fails on `expected 404 to be 201`, a behavioral red. `packages/storage/test/local-room.pg.test.ts` proves concurrent contiguous sequences with the latch pattern, same-command race yielding one message, rollback after append, the 4096-scalar limit at the store, RLS with the bypass-role guard negative, immutability for the app role and the owner, and exact replayed receipts.
- Probe: `scripts/probe-center.mjs` runs the migration first, adds committed, replayed, changed-body 409, scope 404, empty-body 400 and snapshot-after-restart scenarios, and asserts the identity digest with `@agora/contracts/canonical`.
- Same change: feature-map entry `local-room-persistence`, verification skill Drive and Evidence updates, `docs/site/local-room.md` rewritten for L2 with a transaction flow visual, runbook, CLI page, atlas, generated mirror, decisions and AGENTS.md.
